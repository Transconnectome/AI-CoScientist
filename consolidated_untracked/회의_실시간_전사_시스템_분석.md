  - 액션 아이템 추출
  - 화자별 발언 시간 추적
  - 2024년 10월 출시, 지속적 개선 중
- **Intelligent Speakers**
  - 회의실 내 화자 식별
  - 음성 프로필 기반 화자 인식
  - 실시간 전사에 화자 이름 자동 태깅

**Zoom**

  - 화자별 분리된 전사 데이터

**Recall.ai**

- 실시간 오디오/비디오 스트림

**Nylas Notetaker API**
- 회의 봇 자동 참석
- 실시간 전사 및 화자 식별

**AssemblyAI**
- 실시간 스트리밍 전사 API
- 화자 분리 (Speaker Diarization) 지원
- 95개 언어 지원
- 500ms 미만 지연시간
- 2024-2025년 성능 개선: DER 10.1% 향상, cpWER 13.2% 향상

**Deepgram**
- 실시간 및 배치 전사
- 화자 분리 지원
- 30개 이상 언어 지원

- 엔터프라이즈 규모 확장성

**Azure Speech Service**
- 실시간 대화 전사 (ConversationTranscriber)
- 실시간 화자 분리 지원
- 2-10명 화자 최적화
- 다국어 지원

**Google Cloud Speech-to-Text**
- Chirp 3 모델 (V2 API)
- 85개 이상 언어 지원
- 화자 분리 지원
- 배치 및 스트리밍 모드

**NVIDIA Streaming Sortformer**
- 실시간 화자 분리 모델
- 프레임 레벨 분리
- 2-4명 이상 화자 추적
- GPU 최적화 추론
- NeMo, Riva 통합

## 2. 시스템 구축을 위한 필수 작업

### 2.1 아키텍처 설계

#### 2.1.1 전체 시스템 구조

```
[회의 플랫폼] → [오디오 캡처] → [전사 엔진] → [화자 분리] → [분석 엔진] → [노트 생성]
     ↓              ↓              ↓            ↓            ↓            ↓
  Zoom/Teams    Meeting Bot    STT API    Diarization   시간 분석    AI 요약
```

#### 2.1.2 주요 구성 요소

1. **회의 연결 모듈**
   - Meeting Bot 구현 또는 API 활용
   - 플랫폼별 인증 및 권한 관리
   - 실시간 미디어 스트림 수신

2. **오디오 처리 파이프라인**
   - WebRTC/SFU 기반 오디오 스트리밍
   - 오디오 품질 향상 (노이즈 제거, 에코 제거)
   - 멀티 채널 오디오 처리

3. **전사 엔진**
   - 실시간 Speech-to-Text API 통합
   - 스트리밍 모드 지원
   - 다국어 지원

4. **화자 분리 모듈**
   - Speaker Diarization 알고리즘
   - 화자 임베딩 추출
   - 화자 클러스터링 및 추적

5. **발언 시간 분석 모듈**
   - 타임스탬프 기반 발언 시간 계산
   - 화자별 통계 집계
   - 발언 패턴 분석

6. **회의 노트 생성 모듈**
   - LLM 기반 요약 생성
   - 액션 아이템 추출
   - 키워드 및 주제 추출

### 2.3 개발 단계별 작업

#### Phase 1: 기본 인프라 구축 (2-3주)

1. **회의 연결 모듈 개발**
   ```python
   # 예시: Recall.ai API 사용
   import recallai
   
   client = recallai.RecallAI(api_key="your_key")
   bot = client.create_bot(
       meeting_url="zoom.us/j/123456789",
       webhook_url="https://your-app.com/webhook"
   )
   ```

2. **오디오 스트림 수신**
   - WebSocket 연결 설정
   - 실시간 오디오 청크 처리
   - 버퍼링 및 스트리밍 최적화

3. **기본 전사 기능 구현**
   - STT API 통합
   - 실시간 텍스트 출력

#### Phase 2: 화자 분리 구현 (2-3주)

1. **화자 분리 모듈 통합**
   ```python
   # AssemblyAI 예시
   import assemblyai as aai
   
   aai.settings.api_key = "your_key"
   transcriber = aai.Transcriber()
   
   config = aai.TranscriptionConfig(
       speaker_labels=True,
       speakers_expected=5
   )
   ```

2. **화자 추적 로직**
   - 화자 ID 매핑
   - 화자 변경 감지

3. **화자 이름 매핑**
   - 회의 참석자 목록과 매칭
   - 음성 프로필 학습 (선택사항)

#### Phase 3: 발언 시간 분석 (1-2주)

1. **타임스탬프 기반 계산**
   ```python
   def calculate_speaking_time(transcript_segments):
       speaker_times = {}
       for segment in transcript_segments:
           speaker = segment.speaker
           duration = segment.end_time - segment.start_time
           speaker_times[speaker] = speaker_times.get(speaker, 0) + duration
       return speaker_times
   ```

2. **통계 집계**
   - 화자별 총 발언 시간
   - 발언 횟수
   - 평균 발언 길이
   - 발언 비율

3. **시각화**
   - 실시간 대시보드
   - 발언 시간 차트
   - 발언 패턴 그래프

#### Phase 4: 회의 노트 생성 (2-3주)

1. **LLM 통합**
   ```python
   # OpenAI API 예시
   from openai import OpenAI
   
   client = OpenAI()
   
   def generate_meeting_notes(transcript):
       response = client.chat.completions.create(
           model="gpt-4",
           messages=[
               {"role": "system", "content": "회의 노트 생성 전문가"},
               {"role": "user", "content": f"다음 회의 전사를 요약하고 액션 아이템을 추출하세요:\n{transcript}"}
           ]
       )
       return response.choices[0].message.content
   ```

2. **구조화된 노트 생성**
   - 회의 요약
   - 주요 결정사항
   - 액션 아이템 (담당자별)
   - 다음 단계

3. **실시간 업데이트**

   - 주기적 노트 갱신

### 2.4 기술적 도전 과제 및 해결 방안

#### 2.4.1 실시간 처리 지연시간

**문제:**
- 실시간 전사는 낮은 지연시간이 필수
- 네트워크 지연, 처리 시간 누적

**해결 방안:**
- WebRTC/SFU 사용으로 네트워크 지연 최소화
- 스트리밍 STT API 선택 (500ms 미만)
- 로컬 버퍼링 최소화
- 병렬 처리 파이프라인

#### 2.4.2 화자 분리 정확도

**문제:**
- 다중 화자 환경에서 정확도 저하
- 화자 변경 감지 지연
- 겹치는 발화 처리

**해결 방안:**
- 멀티 채널 오디오 활용 (플랫폼별 분리된 스트림)
- 최신 화자 분리 모델 사용 (AssemblyAI, NVIDIA Streaming Sortformer)
- 화자 임베딩 기반 추적
- 회의 참석자 목록 활용

#### 2.4.3 오디오 품질

**문제:**
- 배경 소음, 에코, 낮은 볼륨
- 네트워크 품질에 따른 오디오 품질 변동

**해결 방안:**
- 오디오 전처리 (노이즈 제거, 에코 제거)
- 적응형 게인 제어
- 고품질 마이크 권장
- 오디오 품질 모니터링

#### 2.4.4 확장성

**문제:**
- 동시 다중 회의 처리
- 리소스 사용량 증가
- 비용 관리

**해결 방안:**
- 마이크로서비스 아키텍처
- 큐 기반 비동기 처리
- 오토스케일링
- 비용 최적화된 API 선택

#### 2.4.5 플랫폼별 차이점

**문제:**
- Zoom, Teams, Google Meet 각각 다른 API
- 플랫폼별 제한사항

**해결 방안:**
- 통합 Meeting Bot API 활용 (Recall.ai, Nylas)
- 플랫폼별 어댑터 패턴 구현
- 공통 인터페이스 설계

**인프라:**
