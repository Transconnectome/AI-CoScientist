# 팀즈/줌 실시간 회의 음성 분석 시스템 조사 보고서

## 1. 기존 시스템 현황

### 1.1 상용 솔루션

#### Microsoft Teams
- **Intelligent Recap**: Teams Premium/M365 Copilot 라이선스 필요
  - 실시간 전사 및 화자 식별
  - AI 기반 회의 노트 자동 생성
  - 액션 아이템 추출
  - 화자별/주제별 회의 기록 탐색
  - Intelligent Speakers를 통한 회의실 내 참여자 식별
- **제한사항**: 
  - 실시간 오디오 스트림 API는 C# Local Media Bot만 지원 (Java/Node.js/Python 미지원)
  - Zoom RTMS와 같은 범용 WebSocket API 없음

#### Zoom
- **Real-Time Media Streams (RTMS)**: WebSocket 기반 실시간 API
  - 실시간 오디오/비디오/전사 스트림 제공
  - 화자 분리(diarization) 및 메타데이터 포함
  - 참여자별 개별 오디오 스트림
  - 18개 언어 지원
  - 봇 없이 네이티브 통합 가능
- **Cloud Recording**: 회의 종료 후 전사 제공
- **Live Transcription**: 실시간 자막 (99.05% 정확도)

#### 기타 상용 솔루션
1. **Otter.ai**
   - 실시간 전사 및 화자 식별
   - Zoom, Google Meet, Teams 통합
   - 협업 편집 및 액션 아이템 추출
   - Meeting Bot 자동 참여

2. **AssemblyAI**
   - 실시간 스트리밍 전사 (sub-500ms 지연시간)
   - 화자 분리 지원 (2.9% 화자 수 오류율)
   - 노이즈 환경에서 30% 향상된 성능
   - 250ms 짧은 발화 43% 정확도 향상

3. **Fireflies.ai**
   - 자동 회의 참여 및 전사
   - 화자 라벨링 (Zoom, Google Meet에서 강함)
   - AI 기반 인사이트 추출

4. **Voicenotes**
   - Meeting Bot 모드 (2024년 말 도입)
   - 화자 분리 및 타임스탬프
   - 회의 후 처리 방식

### 1.2 오픈소스/연구용 솔루션

## 2. 시스템 구축에 필요한 작업

### 2.1 아키텍처 설계

#### 핵심 컴포넌트
```
[오디오 입력] → [전처리] → [VAD] → [화자 분리] → [ASR] → [NLP 분석] → [출력]
     ↓              ↓         ↓         ↓         ↓         ↓          ↓
  Teams/Zoom    노이즈 제거  음성 감지  화자 식별  전사      요약      회의 노트
```

#### 실시간 처리 파이프라인
1. **오디오 캡처 레이어**
   - Teams: Local Media Bot (C#) 또는 RTMP 스트리밍
   - Zoom: RTMS WebSocket API 또는 봇 기반 캡처
   - Google Meet: Recall.ai 같은 서드파티 API

2. **전처리 파이프라인**
   - 노이즈 감소 (Spectral Subtraction, Wiener Filter)
   - 에코 제거 (AEC - Acoustic Echo Cancellation)
   - 볼륨 정규화
   - 샘플링 레이트 변환 (일반적으로 16kHz)

3. **Voice Activity Detection (VAD)**
   - 음성/비음성 구분
   - 불필요한 계산 방지
   - 실시간 스트리밍 친화적 알고리즘 필요
   - 예: WebRTC VAD, Silero VAD

4. **화자 분리 (Speaker Diarization)**
   - **세그멘테이션**: 화자 전환점 감지
   - **임베딩 추출**: 화자 특성 벡터 생성
     - ECAPA-TDNN, x-vector, d-vector
     - 192-512 차원 벡터
   - **클러스터링**: 유사한 화자 그룹화
     - K-Means, Spectral Clustering, AHC
     - 실시간: Incremental Clustering, Rolling Buffer
   - **재분할 (Resegmentation)**: 경계 정제

5. **자동 음성 인식 (ASR)**
   - 실시간 스트리밍 ASR
   - 화자 라벨과 텍스트 매칭
   - 예: Whisper, AssemblyAI, Azure Speech

6. **NLP 분석**
   - 회의 요약 생성
   - 액션 아이템 추출
   - 키워드/주제 추출
   - 발언 시간 통계

### 2.2 기술 스택

#### 백엔드
- **언어**: Python (ML/AI), Node.js/Java (API 서버)
- **프레임워크**: 
  - FastAPI/Flask (Python)
  - Express.js (Node.js)
  - Spring Boot (Java)
- **오디오 처리**:
  - librosa, soundfile (Python)
  - WebRTC (실시간 스트리밍)
- **ML/AI 라이브러리**:
  - PyTorch/TensorFlow

  - SpeechBrain

#### 실시간 처리
- **메시지 큐**: Redis Streams, RabbitMQ, Kafka
- **WebSocket**: Socket.io, WebSocket API

- **전사 저장**: PostgreSQL, MongoDB
- **임시 버퍼**: Redis
- **벡터 DB**: Pinecone, Weaviate (화자 임베딩)

#### 클라우드 서비스
- **ASR API**: 
  - Azure Speech Services
  - Google Cloud Speech-to-Text
  - AWS Transcribe
  - AssemblyAI
- **인프라**: 
  - AWS/GCP/Azure
  - Kubernetes (스케일링)

### 2.3 핵심 알고리즘 및 모델

#### 화자 분리 파이프라인
1. **VAD 모델**
   - Silero VAD (경량, 실시간)
   - WebRTC VAD
   - CRDNN (SpeechBrain)

2. **화자 임베딩 모델**
   - **ECAPA-TDNN**: 현재 가장 널리 사용
     - 192-512 차원 임베딩
     - VoxCeleb 데이터셋으로 사전 학습
   - **x-vector**: 전통적 방법
   - **d-vector**: ResNet 기반

3. **클러스터링 알고리즘**
   - **오프라인**: Spectral Clustering, VBx
   - **실시간**: 
     - Incremental K-Means
     - Rolling Buffer 기반 클러스터링
     - AHC (Agglomerative Hierarchical Clustering)

4. **실시간 최적화**
   - Sliding Window (1.5초 윈도우, 0.5초 스트라이드)
   - Look-ahead 메커니즘
   - 동적 화자 수 추정

#### ASR 모델
- **Whisper**: OpenAI, 다국어 지원
- **Wav2Vec 2.0**: Facebook
- **Conformer**: Google
- **상용 API**: AssemblyAI, Azure, Google

### 2.5 기술적 도전과제

#### 실시간 처리 제약
1. **지연시간 (Latency)**
   - 목표: <1초 (실시간 자막용)
   - 도전: 클러스터링은 전체 오디오 필요
   - 해결: Incremental Clustering, Look-ahead

2. **계산 자원**
   - 실시간 처리의 높은 CPU/GPU 요구
   - 해결: 모델 경량화, 최적화

3. **화자 수 가변성**
   - 미리 알 수 없는 화자 수
   - 해결: 동적 클러스터링, 최대 화자 수 제한

#### 정확도 문제
1. **오버랩핑 음성**
   - 여러 화자 동시 발화
   - 해결: Overlap-aware 모델, CSS (Continuous Speech Separation)

2. **노이즈 환경**
   - 회의실 에코, 배경 소음
   - 해결: 전처리 강화, 노이즈 강건 모델

3. **짧은 발화**
   - 250ms 이하 짧은 발화
   - 해결: 최소 세그먼트 길이 조정

#### 통합 복잡도
1. **플랫폼별 API 차이**
   - Teams: C# 제한
   - Zoom: RTMS (좋음)
   - 해결: 추상화 레이어, 서드파티 API 활용

2. **동시성 처리**
   - 여러 회의 동시 처리
   - 해결: 비동기 처리, 큐 시스템

### 2.6 예상 개발 리소스

### 3.1 단기 (빠른 프로토타입)

## 5. 결론

실시간 회의 음성 분석 시스템은 기술적으로 가능하며, 여러 상용 솔루션이 이미 존재합니다. 자체 구축 시에는 실시간 처리, 화자 분리 정확도, 플랫폼 통합의 복잡성을 고려해야 합니다. 

**추천 전략**:
1. 초기: Recall.ai + AssemblyAI로 빠른 프로토타입
2. 검증 후: Zoom RTMS 활용한 커스텀 솔루션
3. 확장: 오픈소스 기반 자체 구축

**핵심 성공 요소**:
- 낮은 지연시간 (<1초)
- 높은 화자 분리 정확도 (DER <5%)
- 안정적인 실시간 처리
- 확장 가능한 아키텍처
