# 팀즈/줌 실시간 화자별 회의 노트 및 발언 시간 분석 시스템 조사 보고서

## 1. 기존 시스템 현황

### 1.1 상용 솔루션

#### Microsoft Teams 내장 기능
- **실시간 전사(Real-time Transcription)**: Teams 자체 전사 기능 제공
- **AI 회의 노트**: Microsoft Copilot을 통한 자동 회의 요약
- **화자 식별**: Intelligent Speakers를 사용한 화자 인식 (2024-2025)
- **발언 시간 분석**: 기본적인 참여자 분석 기능 포함
- **제한사항**: 
  - Enterprise 라이선스 필요 (Copilot: $30/사용자/월)
  - 실시간 화자별 세분화된 분석 기능 제한적
  - API를 통한 커스텀 분석 어려움

#### Zoom 내장 기능
- **자동 자막(Live Transcription)**: 실시간 자막 제공
- **회의 녹음 및 전사**: 클라우드 녹음 후 전사
- **정확도**: 99.05% (Webex 98.71% 대비 27% 적은 오류)
- **제한사항**:
  - 실시간 화자별 세분화 분석 기능 부족
  - API를 통한 실시간 오디오 스트림 접근 제한적

#### 서드파티 AI 회의 어시스턴트

**Otter.ai**
- **주요 기능**:
  - 실시간 전사 및 화자 식별
  - 자동 회의 요약 및 액션 아이템 생성
  - Zoom, Google Meet, Teams 통합
- **가격**: Basic (무료 300분/월), Pro ($16.99/월), Business ($30/월)
- **특징**: OtterPilot 봇이 자동으로 회의에 참여하여 노트 작성

**Fireflies.ai**
- **주요 기능**:
  - 95% 정확도 전사
  - 100+ 언어 지원
  - 화자 인식 및 회의 분석
- **통합**: Zoom, Teams, Google Meet, Aircall, Ringcentral 등
- **특징**: 봇이 회의에 참여하여 자동 녹음 및 전사

**Read.ai**
- **주요 기능**:
  - 실시간 회의 노트
  - 화자별 발언 시간 분석
  - 감정 분석 및 참여도 측정
  - 실시간 대시보드 제공
- **특징**: 회의 중 실시간으로 참여도, 발언 시간, 감정 등을 분석

**MeetGeek**
- **주요 기능**:
  - 화자별 발언 시간 분석
  - 감정 분석
  - CRM 및 프로젝트 관리 도구 연동
- **특징**: 봇 없이도 브라우저 확장 프로그램으로 녹음 가능

**Tactiq**
- **주요 기능**:
  - 실시간 전사 (봇 없이 작동)
  - 60+ 언어 지원
  - 화자 식별
  - AI 요약 및 액션 아이템 생성
- **특징**: Chrome 확장 프로그램으로 작동, 봇이 회의에 참여하지 않음

### 1.2 기술적 솔루션 (API/라이브러리)

#### 화자 분리(Speaker Diarization) API

**AssemblyAI**
- **특징**:
  - 실시간 스트리밍 지원
  - 95개 언어 지원
  - 노이즈 환경에서 30% 향상된 성능
  - 250ms 세그먼트에서 43% 정확도 향상
  - 화자 수 오류율 2.9% (업계 최고 수준)
- **가격**: $0.15/시간
- **용도**: 프로덕션 애플리케이션에 적합

**Deepgram**
- **특징**:
  - 실시간 처리 속도 강조 (경쟁사 대비 10배 빠름)
  - 화자 수 제한 없음
  - 언어 무관 작동
  - Nova-2 음성 인식 모델 통합
- **용도**: 빠른 처리 속도가 중요한 애플리케이션

**Speechmatics**
- **특징**:
  - 정확도 25% 향상 (자체 벤치마크)
  - 클라우드 및 온프레미스 배포 옵션
  - 30+ 언어 지원
  - 최대 화자 수 설정 가능 (2-20명)
- **용도**: 엔터프라이즈 배포, 온프레미스 요구사항

**Gladia**
- **특징**:
  - Whisper + PyAnnote 통합
  - 향상된 화자 분리 모드
  - 스트리밍 지원
- **용도**: Whisper를 사용하는 팀에 적합

#### 오픈소스 솔루션

**PyAnnote.audio 3.1**
- **특징**:
  - 최신 연구 모델
  - GPU에서 2.5% 실시간 팩터
  - 약 10% DER (Diarization Error Rate)
  - 오버랩 음성 처리 개선
- **요구사항**: Python 3.7+, Linux/MacOS, Hugging Face 인증 토큰
- **용도**: 연구 및 커스텀 구현

**NVIDIA Streaming Sortformer**
- **특징**:
  - 실시간 화자 분리
  - 프레임 레벨 다이어리제이션
  - 최소 지연시간
  - 2-4명 화자 추적
  - NeMo 및 Riva와 통합
- **용도**: 실시간 회의 분석, 음성봇, 미디어 방송

**WhisperX**
- **특징**:
  - Whisper + PyAnnote 통합
  - GPU: 실시간보다 빠름 (1시간 오디오를 18-30분에 처리)
  - CPU: 실시간보다 느림 (1시간 오디오를 2-3시간에 처리)
- **요구사항**: RAM 8-16GB, GPU VRAM 4-8GB
- **용도**: 오프라인 처리에 적합

## 2. 시스템 구축을 위해 필요한 작업

### 2.1 아키텍처 설계

#### 전체 시스템 아키텍처
```
[회의 플랫폼] → [오디오 캡처] → [전처리] → [화자 분리] → [음성 인식] → [분석 엔진] → [노트 생성] → [대시보드]
```

#### 주요 컴포넌트
1. **오디오 캡처 레이어**
   - 회의 플랫폼 API 연동 (Teams/Zoom)
   - 실시간 오디오 스트림 수신
   - 오디오 버퍼링 및 청크 처리

2. **전처리 레이어**
   - 노이즈 제거
   - 볼륨 정규화
   - 샘플링 레이트 변환
   - VAD (Voice Activity Detection)

3. **화자 분리 레이어**
   - 실시간 화자 다이어리제이션
   - 화자 임베딩 추출
   - 화자 클러스터링
   - 화자 추적 (Speaker Tracking)

4. **음성 인식 레이어**
   - 실시간 STT (Speech-to-Text)
   - 화자별 텍스트 할당
   - 타임스탬프 생성

5. **분석 엔진**
   - 발언 시간 계산
   - 발언 횟수 분석
   - 대화 패턴 분석
   - 키워드 추출

6. **노트 생성 레이어**
   - 화자별 노트 생성
   - 요약 생성
   - 액션 아이템 추출
   - 타임라인 생성

7. **저장 및 표시 레이어**
   - 데이터베이스 저장
   - 실시간 대시보드
   - 리포트 생성

### 2.2 기술 스택 선택

#### 옵션 1: 클라우드 API 기반 (빠른 개발)
- **오디오 캡처**: Recall.ai 또는 Nylas API
- **화자 분리 + STT**: AssemblyAI Universal-Streaming API
- **분석**: Python (pandas, numpy)
- **노트 생성**: OpenAI GPT-4 또는 Claude
- **백엔드**: Node.js 또는 Python (FastAPI)
- **프론트엔드**: React 또는 Vue.js
- **데이터베이스**: PostgreSQL + Redis

**장점**:
- 빠른 개발 속도
- 높은 정확도 (검증된 API)
- 확장성 용이
- 유지보수 부담 적음

**단점**:
- 비용 발생 (API 사용료)
- 데이터 프라이버시 고려 필요
- 커스터마이징 제한

#### 옵션 2: 하이브리드 (오픈소스 + API)
- **오디오 캡처**: Recall.ai API
- **화자 분리**: PyAnnote.audio 또는 NVIDIA Streaming Sortformer
- **STT**: Whisper (로컬) 또는 AssemblyAI API
- **분석**: Python
- **노트 생성**: 로컬 LLM (Llama 3) 또는 API
- **인프라**: GPU 서버 (NVIDIA GPU 권장)

**장점**:
- 비용 절감 가능
- 데이터 프라이버시 보장
- 커스터마이징 자유도 높음

**단점**:
- 개발 시간 증가
- 인프라 관리 필요
- 성능 튜닝 필요

#### 옵션 3: 완전 자체 구축
- **오디오 캡처**: Teams/Zoom Bot 직접 개발
- **화자 분리**: PyAnnote.audio 또는 NVIDIA NeMo
- **STT**: Whisper 또는 Wav2Vec2
- **분석**: 자체 개발
- **노트 생성**: 자체 LLM 파이프라인
- **인프라**: 고성능 GPU 클러스터

**장점**:
- 완전한 제어
- 데이터 프라이버시 최대화
- 장기적 비용 절감 가능

**단점**:
- 매우 긴 개발 시간
- 높은 기술적 복잡도
- 상당한 인프라 투자 필요

### 2.4 기술적 도전 과제 및 해결 방안

#### 도전 과제 1: 실시간 처리 지연시간
**문제**: 실시간 분석을 위해서는 낮은 지연시간이 필수적
**해결 방안**:
- 스트리밍 API 사용 (AssemblyAI Universal-Streaming)
- 오디오 청크 크기 최적화 (500ms-1s)
- 병렬 처리 파이프라인
- 엣지 컴퓨팅 고려

#### 도전 과제 2: 화자 분리 정확도
**문제**: 비슷한 목소리, 오버랩 음성, 노이즈 환경에서 정확도 저하
**해결 방안**:
- 고성능 화자 분리 모델 사용 (AssemblyAI, NVIDIA Streaming Sortformer)
- 화자 사전 등록 (선택사항)
- 오디오 품질 개선 (노이즈 제거)
- 다중 마이크 입력 활용 (가능한 경우)

#### 도전 과제 3: 비용 관리
**문제**: API 사용료가 회의 시간에 비례하여 증가
**해결 방안**:
- 하이브리드 접근 (중요 회의만 API 사용)
- 로컬 모델 활용 (Whisper, PyAnnote)
- 캐싱 전략 (유사 회의 패턴 재사용)
- 사용량 모니터링 및 알림

#### 도전 과제 4: 데이터 프라이버시
**문제**: 회의 내용의 민감한 정보 보호
**해결 방안**:
- 온프레미스 배포 옵션
- 데이터 암호화 (전송 중, 저장 시)
- 접근 제어 및 권한 관리
- 데이터 보존 정책 설정
- GDPR/개인정보보호법 준수

#### 도전 과제 5: 다중 플랫폼 지원
**문제**: Teams, Zoom, Google Meet 각각 다른 API 구조
**해결 방안**:
- Recall.ai 같은 통합 API 활용
- 플랫폼별 어댑터 패턴 구현
- 공통 인터페이스 설계
